<Section>
Tailwind allows you to register official or third-party plugins with Tailwind that can be used to generate extra utilities, components, base styles, or custom variants. Decanter [makes use](https://github.com/SU-SWS/decanter/blob/main/tailwind.config.js) of some of these plugins, and you can add additional plugins to your project in its `tailwind.config` file. Full information regarding plugins can be found in the [Tailwind docs](<https://tailwindcss.com/docs/plugins>).
</Section>

<Section heading="Official Tailwind plugins used in Decanter v7">
[Aspect Ratio](https://tailwindcss.com/docs/plugins#aspect-ratio): The `@tailwindcss/aspect-ratio` plugin is an alternative to native aspect-ratio support that works in older browsers, and adds `aspect-w-{n}` and `aspect-h-{n}` classes that can be combined to give an element a fixed aspect ratio.

<Deprecated>
  Decanter v8 drops the **Aspect Ratio** plugin, and the `aspect-w-{n}` / `aspect-h-{n}` classes go with it. Use Tailwind's core aspect ratio utilities instead, e.g., `aspect-[16/9]`. Note that while this plugin is loaded it suppresses the core `aspect-*` utilities, so `aspect-video` generates nothing in v7 — `aspect-[16/9]` works today and keeps working in v8.
</Deprecated>

[Container Queries](https://tailwindcss.com/docs/plugins#container-queries): The `@tailwindcss/container-queries` plugin adds new `@{size}` variants like `@sm` and `@md` that let you style an element based on the dimensions of a parent marked with `@container` instead of the viewport.

[Forms](https://tailwindcss.com/docs/plugins#forms): The `@tailwindcss/forms` plugin adds an opinionated form reset layer that makes it easier to style form elements with utility classes.

**[Hocus](https://github.com/iksaku/tailwindcss-plugins#hocus-variant) and [Children](https://github.com/benface/tailwindcss-children)**: are plugins that are included in Decanter's `tailwind.config.js` file, but are not official Tailwind plugins. They are included in Decanter's `tailwind.config.js` file to provide additional functionality to the framework.

<Deprecated>
  The **children** variants are deprecated and will be removed in v8. Tailwind's built-in [`*` variant](https://tailwindcss.com/docs/hover-focus-and-other-states#styling-direct-children) covers all four, with the identical selector:

  | Deprecated | Use instead | Selector |
  | --- | --- | --- |
  | `children:` | `*:` | `& > *` |
  | `children-hover:` | `hover:*:` | `& > *:hover` |
  | `children-focus:` | `focus:*:` | `& > *:focus` |
  | `children-focus-visible:` | `focus-visible:*:` | `& > *:focus-visible` |

  Stacked and prefixed forms translate the same way: `children:children:` becomes `*:*:`, `last:children:` becomes `last:*:`, and `sm:children:` becomes `sm:*:`.

  **Mind the order** on the state variants. `hover:*:underline` gives `& > *:hover` — each child on its own hover, which is what `children-hover:` did. Writing it the other way round, `*:hover:underline`, gives `&:hover > *` — every child styled when the *parent* is hovered. Those are different things.
</Deprecated>

</Section>
